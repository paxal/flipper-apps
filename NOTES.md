# Lessons that apply to every app in this repo

Collected while fixing `games/icecube`; see `games/icecube/NOTES.md` for the
game-specific findings.

## Input handling

- **Do not share one small queue between a fast timer and the keys with zero-timeout
  puts.** A 60 Hz render timer fills an 8-slot queue as soon as the loop falls behind,
  and every key event after that is silently dropped, releases included, which leaves
  a direction stuck. Enqueue at most one pending tick (a `volatile bool` set in the
  timer callback, cleared when the tick is consumed) and size the queue for keys.
- **Latch taps.** If the logic step polls "is the key held", a press and release that
  both land inside one step do nothing. Record each press in a bitmask that the next
  logic step consumes, so a tap always gives one impulse.
- **Run logic on the wall clock**, `furi_get_tick()` against a due time, not by
  counting timer events. Late or coalesced ticks then never slow the game; cap the
  catch-up (4 steps) and resync when paused.
- **Fire on `InputTypePress` for actions that must feel instant** (a shot, a blast).
  `InputTypeShort` only arrives on release, after the whole press. Keep `Short` for
  keys that also have a `Long` meaning, such as Back = pause / long Back = quit.

## Keeping the app killable

- **Never take the game mutex in the draw callback with `FuriWaitForever`.** The
  draw callback runs on the GUI thread; if the app thread hangs while holding the
  mutex, the GUI thread blocks too and the Back key dies with the display. Acquire
  with a short timeout (one frame, ~20 ms) and skip the redraw on failure, so a long
  Back still reaches the app and `loader close` from the CLI still works.
- When everything is frozen anyway: hold Left + Back for ~5 s for a hardware reset,
  or `power reboot` from `ufbt cli`.

## Rendering

- The 2-bit `gray2bit` path (stagger FRC, 3-tick period) costs one full-screen XBM
  bake per 16 ms tick; keep game logic out of that path and only re-render the packed
  frame when the state changed.
- Shared helper: `games/icecube/helpers/gray2bit.[ch]` is a copy of the grayscale POC
  code. Any fix belongs in both until it is factored out.

## Testing without a device

- Keep logic in pure C with no `furi_*` calls so `make -C test` can run it on the host.
- Add a tiny host program that renders every screen to PNG (an 8-bit grayscale PNG
  with stored deflate blocks needs no library; see `games/icecube/test/render_frames.c`).
  Reading those images catches layout and asset bugs that unit tests never see.

## Porting from other machines

- Never trust an extracted asset until it looks like one. A level or sprite table with
  near-uniform byte entropy is compressed or mis-offset, whatever the comments say.
  Count something the original documents (here: 300 pawns) and make the test assert it.
- Generated data files should state the generator and the source file in a header and
  be regenerated by a checked-in script, never hand-edited.
- On the HP-48 Saturn, `B=B-1; GONC loop` runs N+1 times and `?C>=A B, L` means
  "jump to L when C >= A"; both bit the first decoder transcription.
